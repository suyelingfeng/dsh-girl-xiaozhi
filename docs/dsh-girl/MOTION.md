# DSH 娘体感互动：四元数与卡尔曼姿态融合

本功能针对立创·实战派 ESP32-S3 的板载 QMI8658，不需要外接陀螺仪。
沿用板上 GPIO1（SDA）、GPIO2（SCL）和现有 I²C 主机，传感器地址为 `0x6A`。
接入依据是[官方硬件资料](https://wiki.lckfb.com/zh-hans/szpi-esp32s3/open-source-hardware/)
与[官方姿态传感器教程](https://wiki.lckfb.com/zh-hans/szpi-esp32s3/beginner/attitude-sensor.html)。

沿用实战派已有板型、音频接线与固件配置，传感器功能仅在本板启用。

## 怎么玩

开机后先静放约 1.5 秒。校准会以当前摆放姿态作为中立位置；
校准过程中晃动会重新累计静止样本，不会用运动中的数据校准零偏。
开机校准完成后，进入待机即可互动。

- 轻轻倾斜：角色会侧身并小幅移动，界面文字和状态栏保持原位。
- 向两个方向持续倾斜超过 28°、保持约 0.3 秒：分别触发害羞或挥手。
  方向按传感器 X/Y 轴定义，实际左右取决于当前摆放方向。
- 连续摇晃：0.8 秒内累计三次明显加速度脉冲，触发惊讶。
  一次碰撞或长时间维持一个加速度峰值不会重复计为三次摇晃。
- 相对校准姿态倒置超过 135°、保持约 0.35 秒：触发生气。
- 安静放置 45 秒：进入打瞌睡动作；再次拿动会开心醒来。

倾斜、摇晃、倒置动作间有 3 秒冷却；持续保持倾斜或倒置不会重复触发，
需要先回到较小角度再触发下一次。互动表情通常保持 6 秒，之后返回待机。
睡眠表情会一直保持到拿动、关闭互动或进入其他工作状态。

本地互动仅在待机时生效；联网、配网、听话、说话期间不触发。
正常语音或云端表情会使本地互动失效，旧的互动计时器不会把新表情覆盖回待机。
这是本地屏幕互动，不会自动向云端发送消息或主动开启麦克风。

## 语音工具

可通过现有 MCP 接口调用：

- `self.pet.motion.status`：查看四元数 `w,x,y,z`、相对 roll/pitch/yaw、
  陀螺仪零偏、线性加速度幅值、校准状态、样本年龄及未取得新样本的计数
  （`read_errors` 包含传感器尚未就绪和总线读取失败）。
- `self.pet.motion.enable`：参数 `enabled` 为 `true/false`，开关体感互动。
  关闭后恢复本地角色位置；传感器采样仍继续，便于再次打开。
- `self.pet.motion.calibrate`：请求重新校准。工具立即返回，放稳约 1.5 秒，
  再用 `status` 确认 `calibrated=true`。这同时更新中立姿态。

例如：“关闭体感互动”“重新校准姿态传感器”“报告当前倾角和校准状态”。
开关仅在本次运行中生效，重启默认开启；零偏每次启动重新校准。
传感器缺失或初始化失败时，不注册这些工具，原有语音、动画和串口功能照常工作。

## 算法说明

不是对三个欧拉角分别做平滑。实现采用乘法误差状态扩展卡尔曼滤波（MEKF/ESKF）：

1. 名义状态保存单位四元数和三轴陀螺仪零偏，四元数表示传感器坐标到重力参考坐标的旋转。
2. 读取加速度与角速度，按实际采样间隔积分 `q ← q ⊗ Exp((ω−b)dt)`。
   每次更新重新归一化四元数。
3. 用 6×6 协方差跟踪小角度姿态误差与三轴零偏误差，预测包含角速度交叉项和零偏耦合项。
4. 将加速度归一化后与四元数预测的重力方向比较，求卡尔曼增益，同时修正姿态和可观测零偏。
5. 协方差采用 Joseph 形式更新，并在注入小角度误差后变换误差坐标，减少浮点数带来的不稳定。
6. 加速度幅值偏离 1g 超过 0.15g，或方向创新过大时，跳过该次加速度校正，继续陀螺仪预测。
   中等幅值扰动会提高观测噪声。自由落体、快速摇动不会直接当成重力校正。

传感器量程为 ±4g、±512°/s，芯片输出设置为 250Hz，后台任务约 50Hz 读取并融合。
GUI 最多约 25Hz 更新角色倾斜，并由 Rust 进行时间平滑；一个时刻最多保留一个待执行 GUI 回调，避免堵塞主循环。
静止样本累计 75 次进行启动零偏校准；不需要将设备严格水平放置。

六轴 IMU 没有磁力计，**无法提供无漂移的绝对航向**。yaw 是相对角，可能缓慢漂移。
依靠重力可以约束俯仰与横滚，不能消除全部航向误差。
持续的、幅值接近 1g 的平移加速度仍可能影响姿态估计，这属于六轴观测的限制。
体感触发主要使用相对倾斜和线性加速度，不把 yaw 当作可靠罗盘方向。

## 代码位置与维护

- `main/boards/lckfb/szpi-esp32s3/features/motion/pet_attitude.h`：不依赖 ESP-IDF 的四元数与误差卡尔曼解算。
- `features/gestures/gesture_detector.h`：独立的手势状态机。
- `features/motion/dsh_motion.{h,cc}`：I²C 采样、启动校准、线程调度与 MCP 工具。
- `features/pet_display/dsh_pet_display.{h,cc}`：情绪优先级与角色局部变换。
- `lichuang_dev_board.cc`：使用本板专属的 `DshPetDisplay` 并启动可选传感器服务。
- `scripts/tests/pet_attitude_test.cc`：物理合成轨迹、零偏、异常样本、抖动抑制和手势阈值验证。
- `scripts/tests/test_pet_attitude.py`：编译和运行上述测试。

芯片配置中 CTRL2/CTRL3 的 bit7 自检位保持关闭，避免把自检刺激当作真实动作。
所有总线操作设有超时；连续失败后退避。超过 300ms 没有新数据则停止本地互动，
采样间断超过 100ms 会重新建立姿态与零偏校准，避免用一个样本积分整个失联时间。
Emote 显示分支不启用本实现；改动局限于本板 LVGL 路径，未修改公共显示接口。

构建及烧录方法与[主手册](README.md)一致。新增板级源文件后需先重新配置一次构建：

```powershell
idf.py reconfigure build
```

在主机运行算法测试（需要 g++ 或 clang++）：

```powershell
$env:PET_TEST_CXX = "你的 g++.exe 路径"
python -m unittest discover -s scripts/tests -p test_pet_attitude.py -v
```

## 实物验收

查看启动日志应出现 `QMI8658 ready`、`Stationary calibration complete`，
随后约每 10 秒输出一次姿态、校准标志、样本计数和错误计数。
再按“怎么玩”逐项移动设备，检查角色动作；同时说话，确认体感不会抢占语音表情。
实际左右方向、手感与运动过程仍需手持设备检查，静放启动日志不能替代这些验证。

2026-10-28 已在 COM10 实物烧录并采集约 65 秒日志：静止校准成功，
60 秒时累计 2929 个有效样本，静放后自动进入 `sleepy`，未发生崩溃。
详细记录见[验证记录](VALIDATION.md)。Git 版本标签为 `dsh-girl-motion-v1`。
