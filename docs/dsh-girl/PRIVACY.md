# 隐私处理与公开发布

公开源码与本地开发环境分开保存。首次公开发布采用清理后的独立根提交，
不推送旧开发分支、旧标签或本地 Git 配置。来源及版权由首页、
[第三方声明](../../THIRD_PARTY_NOTICES.md) 和各许可证持续保留。

## 不公开的内容

- 原始串口/启动日志、Wi-Fi SSID 和密码、激活码、设备 UUID/MAC、服务 token。
- NVS、整片 Flash 备份、烧录产物、SDK/工具链缓存、托管组件与本机生成配置。
- 用户目录、私人绝对路径、真实 `.vscode/settings.json` 和本机环境覆盖脚本。
- 本机旧提交、旧标签及其中可能出现的机器设置。

公开仓库仅提供 `settings.example.json`；个人设置、`.env`、日志、密钥文件和构建目录
由 `.gitignore` 排除。公开提交使用项目公开身份和 GitHub noreply 邮箱，
不上传本机 Git 的真实姓名/私人邮箱。项目公开 GitHub 账号及上游作者署名保留。

设备凭据从运行时配网及激活获得，不写入源码。OTA 查询地址仍是服务配置/激活入口，
不是嵌入的个人凭据，不能为隐藏信息而随意删除或改为空。

## 发布前检查

```sh
python scripts/check_public_privacy.py
python scripts/check_public_privacy.py --history
git diff --check
```

脚本检查 Git 跟踪文件，发现常见密钥格式、带密码的 URL、个人用户目录和不应发布的
产物时，只输出文件、行号和类型，不显示匹配值。`--history` 检查公开仓库所有可达提交。
它不检查被忽略文件，也不能识别所有自由格式密码、图片内容或未知服务密钥，
因此不能取代人工审查；提交截图和日志前仍须删除或遮挡个人信息。

已有公开内容若出现真实凭据，应先撤销/轮换，再清理历史；仅删除当前文件不能消除旧提交。
不要用 `git push --mirror` 或 `git push --tags` 把本地旧开发历史重新发布。
本项目首次公开版本为 `v0.1.0`，后续仅从公开历史继续提交。
